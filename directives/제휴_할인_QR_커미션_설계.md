# 씬짜오 제휴 할인 — QR + 선불 커미션 지갑 설계도 (v0 초안)

> 목적: 자체 제휴 프로그램이 없는 동네 식당·서비스 업소를 앱으로 유도하고, **사람 손 없이 자동으로** 커미션을 받는 구조.
> 원리: 그랩식 "방문 기록(어트리뷰션) + 식당이 커미션 부담"을 **QR 스캔 + 선불 지갑**으로 우리 버전화.
> 상태: 설계 초안 (미구현). 결정·승인 후 v1 착수.

---

## 0. 한 줄 요약

**식당은 QR 스티커만 붙이고 지갑에 미리 충전한다 → 손님이 앱으로 스캔하면 할인받고, 그 순간 커미션이 지갑에서 자동 차감된다 → 잔액 0이면 자동 정지.** 수금·집계를 우리가 쫓아다닐 일이 없다.

---

## 1. 전체 흐름 (한눈에)

```
[식당]                    [손님 / 앱]                  [씬짜오 서버]
 │ QR 스티커 부착            │                              │
 │ 지갑 100만동 충전 ───────────────────────────────────▶ 지갑 잔액 100만
 │                          │ 옐로/검색에서 "씬짜오 할인" 배지 봄
 │                          │ 식당 QR 스캔 ──────────────▶ ① 잔액 확인(>커미션?)
 │                          │                              ② 방문기록 생성
 │                          │                              ③ 커미션 2만 자동차감 → 잔액 98만
 │                          │ ◀── 할인 확인증(10%·코드·5분타이머)
 │ 점원이 확인증 보고 할인 적용 ◀┘                          │
 │                          │                              │ 잔액<10만 → 자동 OFF + 충전알림
```

핵심 = **스캔 한 번이 "방문 기록"이자 "커미션 차감" 트리거.** 이 기록이 그랩 예약 기록과 같은 역할(어트리뷰션).

---

## 2. 데이터 구조 (최소)

- **제휴업소(Merchant)**: `id`(옐로 id 연결), `상호`, `할인율`(10%), `방문당커미션`(20,000동), `지갑잔액`, `상태`(활성/일시정지/잔액부족), `qr토큰`(고유)
- **방문기록(Redemption)**: `id`, `업소id`, `손님id`, `시각`, `상태`(스캔됨/만료), `적용할인`, `차감커미션` ← **어트리뷰션 증거**
- **지갑거래(WalletTx)**: `업소id`, `유형`(충전/차감), `금액`, `차감후잔액`, `참조`(방문id 또는 입금id), `시각`
- **손님(User)**: 기존 Firebase Auth 그대로 재사용

---

## 3. 커미션이 "자동"으로 도는 핵심 = 선불 지갑

그랩은 식당에 줄 배달정산금에서 커미션을 빼서 수금이 필요 없다. 우린 줄 돈이 없으니 **선불(prepaid)** 로 뒤집는다:
- 식당이 **미리 충전** → 방문마다 **자동 차감** → 잔액 0이면 **자동 노출 정지**.
- 결과: 떼일 위험 0, 월말 수금 0, 사람 개입 0. **이게 무인 자동화의 심장.**

## 4. 솔직한 함정과 해결 (되는지 판정)

| 함정 | 위험 | 해결 | 판정 |
|---|---|---|---|
| **충전 결제 수단** | 매번 계좌이체 확인하면 반자동 | v1=계좌이체+어드민 입금확인 / v2=VNPay·MoMo 연동 자동충전 | ✅ v1 가능, v2로 완전자동 |
| **점원이 못 알아봄** | 소규모 식당 IT 약함 | 손님이 스캔→ *식당은 확인증 화면만 보면 됨*(설치=스티커뿐). 1장 가이드 | ✅ 부담 최소 |
| **안 사고 스캔만** | 가짜 할인 | 스캔 후 5분만 유효 + 1인 1일 1회 + 점원 눈 확인 | ✅ 소액이라 충분 |
| **식당이 가입 안 함** | 채택 실패 | 24년 신뢰 + 옐로 3,700 + 교민 독자 지렛대. *이미 광고하는 업소부터* | ⚠️ 영업이 관건(기술 아님) |

→ **기술적으로는 v1 전부 구현 가능. 진짜 변수는 "업소 영업"이지 시스템이 아니다.**

## 5. 작업 분리 — 누가 뭘 하나 ★ (핵심)

### 🟧 우리(씬짜오)가 만들고/하는 것
**[앱 — chao-vn-app]**
- 옐로/검색/상세팝업에 **"씬짜오 할인 N%" 배지**
- **"할인받기(QR 스캔)" 버튼** + 카메라 스캔
- **할인 확인증 화면** (할인율·코드·5분 타이머·업소명)
- **내 할인 내역** (언제 어디서 얼마)

**[백엔드 — daily-news-final]**
- 스캔 API: 잔액확인 → 커미션차감 → 방문기록 생성 (원자적 처리)
- 자동 일시정지(잔액부족) + 충전 알림
- 데이터: 업소·방문기록·지갑

**[어드민 — daily-news 관리화면]**
- 제휴업소 등록 / 할인율·커미션 설정
- 지갑 충전 확인(v1 입금확인) / 잔액·방문·정산 리포트

**[운영]**
- 업소 모집(영업) · 입금확인(v1) · 1장 가이드 · QR 스티커 출력·전달

### 🟦 대상 업소(식당)가 하는 것 — *최대한 적게*
- **가입 시(1회)**: 할인율·방문당 커미션 합의 + 지갑 첫 충전(계좌이체)
- **설치**: 받은 **QR 스티커를 카운터/테이블에 부착** ← 이게 설치의 전부
- **운영 중**: 손님 **할인 확인증 화면 보고 할인 적용**(점원) / 잔액 떨어지면 **재충전**
- 집계·정산·노출제어는 **전부 우리가 자동** → 업소는 손 안 댐

> 설계 원칙: 업소의 작업을 "스티커 붙이기 + 확인증 보기 + 가끔 충전" 3개로 고정. 더 늘면 채택 실패.

## 6. 단계 (phasing)

- **v1 (MVP, 수동 충전)**: 손님이 식당 정적 QR 스캔 → 할인+자동차감. 충전=계좌이체+어드민확인. 업소 5~10곳 파일럿.
- **v2 (완전 자동)**: VNPay/MoMo 연동 자동충전, 업소용 셀프 대시보드(잔액·내역 직접 확인), 자동 충전알림.
- **v3 (확장)**: % 기반 커미션(영수증 입력/POS연동), 손님 리뷰·재방문 쿠폰, 카테고리 확장(미용·병원·서비스).

---

## 7. 열린 결정 사항 (착수 전 정할 것)
1. 커미션 단위 = **방문당 정액**(쉬움) vs **결제액 %**(정확하나 금액 입력 필요) → v1은 정액 추천
2. QR 방향 = **손님이 식당 QR 스캔**(식당 부담 최소, 추천) vs 식당이 손님 QR 스캔(기록 더 강함)
3. 충전 최소금액·방문당 커미션 기본값 (예: 첫충전 100만동, 방문당 1~3만동)
4. 파일럿 업소 카테고리 (한식당부터?)
